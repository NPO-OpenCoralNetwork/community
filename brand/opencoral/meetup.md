# 最初の集まりの進め方(案)

東京周辺で開く、最初の2回の集まりの案です。まだ案なので、団体で確かめてから使います。会場はまだ決まっていません(`facts.md`)。

| 回 | 来る人 | 目的 |
| --- | --- | --- |
| 0回目 | 知り合いや団体の人(4〜8人) | 本番の写真を撮る。進め方を試す |
| 1回目 | ページや広告を見て登録した人 | 最初の集まり。2回目にも来てもらう |

進め方は、ページ(`content.yaml`)で約束していることに合わせました。

- まちや暮らしで気になっていることを持ち寄り、AIで整理しながら話す会です。
- 持ち物は、気になっていることを1つ。スマホかパソコンがあれば、AIをその場で一緒に試せます。
- 専門知識や経歴は問いません。
- 登録すると、参加者のチャットへの招待と、集まりの案内がメールで届きます。
- 顔がはっきり写る写真をサイトや広告に使うときは、あらためて書面で同意をもらいます。

## 決めること

| 項目 | 案 |
| --- | --- |
| 日時 | 土日の夕方か、平日の夜。2時間 |
| 会場 | 窓があり、暖かい色の灯りがある部屋。Wi-Fi と電源があり、10人ほど座れる。貸し会議室、レンタルスペース、区や市の施設など |
| 定員 | 部屋に座れる人数。決めたら、ページの「次の集まり」にも書く |
| 参加費 | 決まっていない(ページの `[参加費]`) |
| 使うAI | 入力した内容を学習に使わない設定にできるもの。団体のアカウントを用意する |
| チャット | Discord か Slack(決まっていない) |
| オンライン | 1回目は会場だけにするか、配信もするか |

- 0回目の会場の写真が、ページの最初の画面の写真になります。写真の決まり(lp-build の `references/photo-rules.md`)に合う部屋を選びます。青白い蛍光灯しかない会議室は避けます。
- 決めたことは、ページに書く前に `facts.md` に書きます。決めた日と、だれから聞いたかも書きます。

### AI の使い方

ページの運営の約束に、「相談の内容や参加者のデータを、AIの学習には使いません」と書いています。集まりでも、この約束を守ります。

- 基本は、団体が用意したアカウントを、学習に使わない設定にして使います。画面に映して、組ごとに一緒に操作します。
- 自分のスマホやパソコンで使う人には、学習に使わない設定のしかたを、最初の説明で案内します。使う AI ごとに、手順を用意しておきます。
- どちらの場合も、名前や住所など個人が分かることや、人に知られたくないことは入れないように伝えます。

### 定員を超えたとき

- 1回目に参加するかは、案内のメールへの返事の早い順で決めます。定員を超えた人には、次の回を案内します。
- 広告はすぐには止めません。登録は1回の集まりへの申し込みではなく、コミュニティへの登録だからです。Ad Grants では、毎月1件以上の登録も要ります。
- あふれる回が続くなら、回を増やすか、広い会場にします。

## 0回目(撮影を兼ねる)

- **時間:** 日の入りをまたぐ時間にします。冬の東京の日の入りは16時半ごろです。日の入りの30〜60分前に会場に入って準備します。
- **人:** 写ってもよい人だけを呼びます。写る人全員から、当日、書面で同意をもらいます(下の同意書の案)。
- **撮る人:** 最初の1回は、プロに頼むのがおすすめです。契約には、次のことを書きます。
  - 著作権を譲ってもらうか、使ってよい範囲を決めるか
  - 使う媒体(サイト、広告、SNS)と期間
- **進め方:** 1回目と同じ進め方で、本当に集まりをします。撮るために演じてもらうより、自然な写真になります。進め方の練習にもなります。
- **撮るもの:** いまのページの写真の枠ごとに撮ります。向きと大きさは、`photo-rules.md` の「枠ごとに要る写真」のとおりです。

| 写真 | ページで使う場所 | 撮るもの |
| --- | --- | --- |
| `hero-h`、`hero-v` | 最初の画面(パソコン、スマホ) | 日の入りのあと、灯りを点けた会場で、2〜4人が作業か会話をしているところ。横長と縦長を別々に撮る |
| `present` | 次の集まり | 前で一人が話し、ほかの人が聞いているところ |
| `work` | AIの勉強会 | 長机で、パソコンに向かって作業しているところ |
| `town` | まちの課題を解く試み | 会場の近くの通り。同じ日の夕方に、外で撮る |
| `talk` | 居場所づくり | 机を囲んで話しているところ |

どの写真も、作業や会話の途中を撮ります。カメラ目線やポーズはなしです。

撮ったあとは、次の順で進めます(lp-build の手順の4)。

1. 写真を選び、lp-build の `images.py grade` で色調をそろえて、`brand/opencoral/photos/` に同じ名前で置く。
2. `content.yaml` の `alt`、`caption`、`focal` を、新しい写真に合わせて直す。
3. `photos/CREDITS.md` と、`content.yaml` の `credits` を直す。団体で撮った写真だけになったら、`credits` の `items` を空にする。
4. ページを組み立て直し、design-review で点検する。

## 1回目の進め方(2時間)

| 時間 | すること |
| --- | --- |
| 0:00〜0:10 | 受付。名札を書き、ストラップを選んでもらう(写ってよい人と、よくない人で色を分ける) |
| 0:10〜0:20 | あいさつ。団体と、この集まりのこと。写真を撮るときの決まりと、AIに入れないこと |
| 0:20〜0:40 | 自己紹介。呼んでほしい名前と、気になっていることを1つ |
| 0:40〜1:10 | 3〜4人の組に分かれ、気になっていることをAIで整理してみる。スマホやパソコンがない人は、同じ組の人の画面を一緒に見る |
| 1:10〜1:40 | 組ごとに話し合い、次に小さく試すことを1つ決める。決めるのは人です |
| 1:40〜1:55 | 組ごとに発表。次回の日程と、参加者のチャットの案内 |
| 1:55〜2:00 | 片付け |

## 準備とそのあと

送るメールの文面は、`emails.md` にあります。

| いつ | すること |
| --- | --- |
| 登録があるたび(なるべくその日のうちに) | 参加者のチャットへの招待と、次の集まりの案内を送る。参加するかの返事をもらう |
| 会場と日時が決まったら | 下の「会場と日時が決まったら」の順に書き入れる |
| 3週間前まで | 会場を予約する |
| 1週間前 | 参加すると返事をした人に、日時、会場、持ち物を送る |
| 前日 | 確認のメールを送る |
| 当日 | 登録した人の一覧(管理ツールで見る)、名札、ストラップ2色、延長コード、モニターとつなぐケーブル。撮影する日は同意書も |
| 2日以内 | お礼のメールと、次回の日程を送る。チャットにまだ入っていない人には、招待をもう一度送る |
| 2日以内 | 来た人の数、初めて来た人の数、2回目以降の人の数を数える |

### 会場と日時が決まったら

1. `facts.md` に、日時、会場、参加費、定員を書く。決めた日と、だれから聞いたかも書く。
2. `content.yaml` の「次の集まり」を直し、ページを組み立て直す。
3. `ads.md` の「毎月すること」にある「会場が決まったとき」を進める。広告を出す地域を、会場に通える範囲に絞る。

### 預かる情報

- 集まりで預かる情報は、プライバシーポリシー(`pages.yaml` の `privacy`)の「預かる情報」と「使う目的」に書いてあります。そこに書いていない情報は預かりません。
- 受付では、登録した人の一覧を管理ツールで見て、来たかどうかを記録します。紙の名簿は作りません。記録するのは、呼んでほしい名前と、来たかどうかだけです。
- 同意書は紙で書いてもらい、鍵のかかる場所に保管します。
- 広告の効果を見るのに使うのは、人数だけです(`ads.md` の「毎月すること」)。
