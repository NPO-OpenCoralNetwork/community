# 空き家活用・コミュニティ拠点プロジェクト

特定非営利活動法人 Open Coral Network が、東京近郊の空き家を活用し、代表者の住居と、音楽・アート・AI・地域交流を行うコミュニティ拠点を確保するための作業場です。Claude Code のサブエージェントで、物件、自治体の制度、交通、資金を調べ、問い合わせの準備と記録までを進めます。

## 中身

```
community/
├─ .claude/agents/                  サブエージェントの設定(Claude Code が読み込む)
│  ├─ property-researcher.md        空き家・賃貸・売買の物件の調査
│  ├─ municipality-researcher.md    自治体の制度、所有者とのマッチングの調査
│  ├─ access-researcher.md          鉄道・バスの交通アクセスの調査
│  ├─ funding-researcher.md         助成金・補助金・資金調達の調査
│  └─ outreach-manager.md           問い合わせ文の作成、進み具合の管理
└─ projects/akiya-hub/
   ├─ CLAUDE.md                     プロジェクト全体の指示(メインエージェントの役割、運用ルール)
   ├─ README.md                     このファイル。動かし方
   ├─ docs/project-plan.md          企画書
   ├─ data/
   │  ├─ README.md                  列と値の決まり
   │  ├─ properties.csv             物件候補
   │  ├─ municipalities.csv         自治体・制度一覧
   │  ├─ funding.csv                自治体以外の資金(助成金、融資、寄付など)
   │  └─ outreach.csv               問い合わせ履歴
   ├─ drafts/                       問い合わせ文の下書き(送る前の案)
   ├─ reports/                      調査レポート
   └─ scripts/check_data.py         データの点検
```

このリポジトリには、参加登録ページの作業もあります。混ざらないよう、このプロジェクトのファイルは `projects/akiya-hub/` にまとめています。サブエージェントの設定だけは、Claude Code が読み込む場所(リポジトリのルートの `.claude/agents/`)に置いています。

## しくみ

```
          人(決める、承認する、送る)
               ↑ 報告・質問  ↓ 依頼・答え
        メインエージェント(メインのセッション)
        進行管理 / 調査結果の統合 / 優先順位の判断 / 企画書の更新
   ┌──────────┬───────────┼───────────┬──────────┐
property-  municipality-  access-   funding-   outreach-
researcher  researcher   researcher researcher  manager
   │            │            │          │          │
properties  municipalities properties  funding   outreach.csv
  .csv         .csv       (交通の列)   .csv      drafts/
   └────────────┴──── reports/ (調査レポート) ────┴──────────┘
```

- **メインエージェント**は、Claude Code のメインのセッションです。専用の設定ファイルはなく、`projects/akiya-hub/CLAUDE.md` の指示で動きます。リポジトリの `AGENTS.md` から、この指示を読むよう案内しています。
- **サブエージェント**は、メインエージェントが仕事を任せる専門の担当です。それぞれ自分のファイルだけを直します。
- サブエージェントには、ファイルを読み書きする道具と、ウェブを検索して読む道具だけを渡しています。メールを送る道具や、コマンドを動かす道具は渡していません。

## 準備

- Claude Code(ターミナル、デスクトップアプリ、Claude Code on the web のどれでも)
- Python 3.9 以上(点検スクリプトに使う。追加のパッケージは要らない)
- 外のサイトに出られるネットワーク(調査に使う)

## 動かし方

### 1. 開く

- **ターミナル**:リポジトリのルートで `claude` を起動します。`projects/akiya-hub/` で起動しても、サブエージェントは読み込まれます。
- **Claude Code on the web**:claude.ai/code で、このリポジトリを選んでセッションを始めます。

サブエージェントが読み込まれたかは、入力欄で `@agent-` と打つと出る候補で確かめられます。

### 2. メインエージェントに頼む

ふつうの言葉で頼みます。メインエージェントが、企画書を読み、サブエージェントに仕事を分けます。

- 「空き家プロジェクトを進めて。企画書を読んで、次にやることを提案して」
- 「企画書の『決めること』に答えます。範囲は〇〇、予算は〇〇です。企画書を直して」
- 「〇〇市と△△市で、空き家バンクと支援制度を調べて、物件も探して」
- 「調べた結果をまとめて、候補の順位を企画書に書いて」
- 「募集中の候補が、まだ募集しているか確かめ直して」

最初は、企画書の「11. 決めること」の1〜5(範囲、基準の駅、予算、条件、借りるか買うか)に答えると、調査が進めやすくなります。

### 3. サブエージェントを名指しで呼ぶ

文で名前を言うか、`@agent-<名前>` で呼びます。

| サブエージェント | 頼み方の例 |
| --- | --- |
| `property-researcher` | 「property-researcher で、〇〇市の戸建てを、賃貸と売買の両方で探して」 |
| `municipality-researcher` | 「@agent-municipality-researcher 〇〇市の空き家バンクと、改修の補助を調べて」 |
| `access-researcher` | 「access-researcher で、現行候補の物件から新宿駅と東京駅までの時間を調べて」 |
| `funding-researcher` | 「funding-researcher で、拠点の改修と音響の設備に使える助成金を探して」 |
| `outreach-manager` | 「outreach-manager で、P-003 の掲載元の不動産会社への問い合わせ文を作って」 |

### 4. 問い合わせの流れ

送るのは、人が全文を確かめて承認したあとだけです。

1. `outreach-manager` が下書きを作る(`drafts/O-001.md`、`outreach.csv` の状態は「下書き」)。
2. メインエージェントが全文を見せて、承認を求める(状態は「承認待ち」)。
3. 人が承認する。メインエージェントが承認日と承認した人(役割)を書く(状態は「承認済み」)。
4. 人が、宛名や連絡先を埋めて送る。「O-001 を送った」と伝えると、送信日が書かれる(状態は「送信済み」)。
5. 返事が来たら、要旨を伝える。`返事の要旨` に書かれ、物件や制度の事実は、出典を `O-001` にしてデータに入る。

### 5. 点検する

データを直したら、リポジトリのルートで点検します。メインエージェントも、統合のたびに動かします。

```sh
python3 projects/akiya-hub/scripts/check_data.py
```

- **NG**:決まりに反しています。直すまで終了コードが 1 です。例:出典URL のない「確認済み」、募集終了の物件を候補にしている、電話番号やメールアドレスが書いてある、承認日のない「送信済み」。
- **注意**:確かめ直すものです。例:募集中の確認日から14日を過ぎた、年度が変わった制度、締切や期日を過ぎたもの。

### 6. 残す

- Claude Code on the web では、push しないと、セッションのコンテナが消えたときに変更も消えます。作業の終わりに「変更をコミットして push して」と頼みます。エージェントは、頼まれるまで push しません。
- **このリポジトリは公開されています。** 名前、電話番号、メールアドレス、番地、代表者の住所や家計、交渉の詳しい中身は書きません。詳しい記録を残す非公開の場所は、企画書の「決めること」の8で決めます。

## 承認が要ること

エージェントは、次のことを、承認なしにはしません(`CLAUDE.md` の運用ルール7)。

- メール、問い合わせフォーム、郵送、SNS のメッセージを送ること
- 外部サービスへの会員登録、ログイン、物件の問い合わせボタン
- メールの下書きを外部サービス(Gmail など)に作ること
- 内見や相談の予約、制度や助成金の申請、申込、契約、支払い
- 公開、push、外部への投稿

## 運用ルール

くわしくは [CLAUDE.md](CLAUDE.md) にあります。要点は次のとおりです。

1. 最新情報は、必ず出典URLと確認日を記録する
2. 確認済み・未確認・推測を区別する
3. 募集終了物件を、現行候補として扱わない
4. 家賃5万円を、検索の上限にしない
5. 所有者との直接交渉や、柔軟な契約を重視する
6. NPO活動と居住の両立の可能性を調べる
7. メールの送信や外部サービスへの登録は、必ず事前に承認を求める

## Codex で使うとき

サブエージェントは Claude Code の機能です。Codex では、`projects/akiya-hub/CLAUDE.md` を読ませてメインのセッションで進めます。`.claude/agents/` の各ファイルは、担当ごとの手順書として読めます。
