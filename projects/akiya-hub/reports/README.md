# 調査レポート

サブエージェントが書く調査レポートの置き場です。1回の調査で1ファイルを書きます。メインエージェントは、これを読んで企画書(`docs/project-plan.md`)にまとめます。

## ファイル名

`YYYY-MM-DD-<エージェント>-<題>.md`

- `<エージェント>` は `property`、`municipality`、`access`、`funding`、`outreach` のどれか
- `<題>` は半角の英数字とハイフン。例:`2026-11-10-municipality-tama-area.md`
- 前のレポートを直さない。新しく調べたら、新しいファイルを書き、前のレポートの名前を「前の調査」に書く

## 書き方

- 事実には、表で出典URL と確認日を付ける。
- 確度(確認済み、未確認、推測)を付ける。推測は「推測:」で始め、根拠を書く。
- 名前、電話番号、メールアドレス、番地を書かない(`projects/akiya-hub/CLAUDE.md` の「個人情報と公開」)。
- 日本語で、短い文で書く。

## ひな形

```markdown
# <題>

- 書いたエージェント:<名前>
- 調べた日:YYYY-MM-DD
- 頼まれたこと:<メインエージェントからの依頼の要点>
- 範囲:<地域、条件>
- 前の調査:<前のレポートのファイル名。なければ「なし」>

## 要点

- <3〜5行。判断に使えることを先に。確度を付ける>

## わかったこと

| # | 内容 | 確度 | 出典URL | 確認日 |
| --- | --- | --- | --- | --- |
| 1 | | | | |

## 推測

- 推測:<考えたこと>。根拠:<何から考えたか>

## 確かめられなかったこと

- <開けなかったページ、登録が要ったサイト、見つからなかった情報>

## データに書いたこと

- `data/<ファイル>.csv`:<追加した ID、直した ID と、何を直したか>

## 次にやるとよいこと

- <だれが何をするか>

## 人に決めてほしいこと

- <決めること。なければ「なし」>
```
