# 実装の決まりと、これまでにはまった点

## テンプレートの約束ごと

`assets/site-template/` のページは、次の目印で JavaScript と確認用のスクリプトにつながっています。名前を変えるときは `main.js` と design-review のスクリプトも直します。

| 目印 | 役割 |
| --- | --- |
| `form[data-signup]` | 参加登録フォーム。`data-endpoint`(送信先)と `data-redirect`(送信後のページ) |
| `#f-name`、`#f-mail` と、それぞれの `aria-describedby` の先(`#f-name-err` など) | 必須の2つの欄と、そのエラー表示 |
| `.form-status` | 送信時のまとめの表示(`role="status"`) |
| `#join-done` | `data-redirect` が空のときに出す受付完了の表示 |
| `input[name="website"]` | ボット対策の見えない欄。送信前に取り除く |
| `[data-hero-cta]` | 最初の画面のボタン。見えているかでスマホ下部のボタンの出し入れを決める |
| `[data-sticky-cta]` | スマホ下部の登録ボタン。最初の画面と `#join` が見えていないときだけ出す |
| `#meetup`、`#acts`、`#join` | メニューの行き先 |

## 画像

- 最初の画面の写真は `<picture>` で、スマホ(760px 以下)に縦の写真、それ以外に横の写真を出す。AVIF、WebP、JPEG の順に `<source>` を並べ、最後の `<img>` が JPEG。
- 最初の画面の `<img>` には `fetchpriority="high"` を付け、`loading="lazy"` は付けない(表示が遅くなる)。ほかの写真は `loading="lazy" decoding="async"`。
- すべての `<img>` に `width` と `height` を入れる(読み込み中に画面がずれない)。
- `sizes` は実際の表示幅に合わせる。最初の画面は `object-fit: cover` で切り抜くので、画面の高さで決まる幅も考える(`build_site.py` が写真の縦横比から計算する)。
- スマホ用の最初の画面の写真は、幅 828px で 120KB 前後に収める(JPEG の品質 70)。

## フォーム

- 必須は2つ。`autocomplete="nickname"` と `autocomplete="email"`、メール欄に `inputmode="email"`。
- JavaScript が動くときは独自の入力チェック(`form.noValidate = true`)を使い、動かないときはブラウザの標準チェックに任せる。そのため HTML には `novalidate` を書かない。
- メールアドレスは送信前に全角を半角にそろえる(`normalize('NFKC')`)。日本語入力のまま打った人を弾かない。
- 送信先が応答しないときは15秒で打ち切り、エラーを出してボタンを戻す。ボタンにフォーカスを戻す。
- 戻るボタンでページがそのまま復元されたとき(bfcache)に、送信中の表示を戻す。
- エラーは欄の下に出し、送信時のまとめは直した数に合わせて更新する。

## アクセシビリティ

- 文字と背景のコントラストは 4.5:1 以上(24px 以上の大きな文字は 3:1 以上)。写真の上の文字は、写真のいちばん明るいところで測る。足りなければ文字の下だけを暗くするグラデーションを敷く(D3 は下から 270px、504px の位置で区切ったグラデーション)。
- 押せるところは高さ 44px 以上。
- フォーカスの枠を消さない(`:focus-visible` に 3px の枠)。
- 本文へのスキップリンク、`<main>`、見出しの順番(h1 は1つ)。
- 動きは `prefers-reduced-motion` で止める。

## これまでにはまった点

デザインを作る途中で実際に起きたことです。同じ形のコードを書くときは確かめてください。

- **リセットの詳細度が高すぎて余白が消えた。** `.d3 h2 { margin: 0 }` のようなリセットは、`.acts-head { margin-bottom: 56px }` より強い。リセットは `:where(h1, h2, …)` で詳細度を 0 にする。
- **ボタンの文字が背景と同じ色になった。** `.d3 a { color: inherit }` が `.btn-light { color: … }` に勝った。ボタンの色は同じかそれ以上の詳細度で指定する。
- **`hidden` を付けても消えなかった。** `.form { display: flex }` が `[hidden] { display: none }` に勝つ。`.form[hidden] { display: none }` を足す。
- **フォームの欄の名前が、フォームの機能を上書きした。** `name="style"` の欄があると `form.style` がその欄を返し、デザインキャンバスの部品が壊れた。`name`、`action`、`method`、`submit`、`style`、`id`、`length`、`elements` などの名前は欄に付けない。
- **最初の画面の高さを固定したら、ノートパソコンでボタンが画面の外に出た。** 高さは `clamp(600px, 100svh, 1000px)` のように画面の高さに合わせる(スマホは `clamp(560px, 100svh, 844px)`)。
- **写真の上の文字が、明るいランプに重なって読めなかった。** 暗幕は % ではなく px で区切り、文字のある下の部分だけを暗くする。写真の明るいところで測る。
- **見出しの「、」のあとに穴が空いた。** palt が効かない書体だったため。[jp-typography.md](jp-typography.md) を参照。
- **写真ごとに色調がばらばらだった。** 1枚だけ冷たい青や、昼の白い部屋が混ざると、そろって見えない。[photo-rules.md](photo-rules.md) の色調の処理を全部にかける。
- **スマホでは横長の写真の中央26%しか見えなかった。** 縦の写真を別に用意する。
- **デザインキャンバスの部品は `file://` では動かない。** 確かめるときは `python3 -m http.server` でローカルのサーバーを立てる。キャンバスの中では `100vh` が板の高さになるので、`vh` は上限つきの `clamp()` の中だけで使う。
