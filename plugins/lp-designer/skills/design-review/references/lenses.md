# 観点ごとの確かめ方

スクリプトの数値とスクリーンショットを見ながら、観点ごとに確かめます。ここに書いた基準は、D3「夕方の写真」の参加登録ページを作ったときに、実際に問題になったことから決めています。

## 1. 見た目

スクリーンショット(パソコンの最初の画面、スマホの最初の画面、ページ全体)を必ず自分の目で見てから判断します。

- **最初の画面:** 写真1枚が全面にあり、左下に見出しとボタン、右下に小さなキャプションだけがある。見出しとボタンのかたまりが画面の高さの35%前後に収まっている。見出しが写真の主役(人)を隠していない。
- **写真:** 色調がそろっている(1枚だけ冷たい青、昼の白い部屋が混ざっていない)。切り抜きで主役が切れていない(スマホの 4:3、活動の最後の 21:9 も見る)。素材写真の決まり文句(カメラ目線の笑顔、握手など)がない。
- **空欄:** `[写真]` のような空の欄、灰色の箱、「準備中」がない。
- **余白:** 節と節の間がそろっている。見出しが写真や罫線にくっついていない(リセットの CSS で余白が消えることがある)。
- **飾り:** 札、番号の飾り、ピル、絵文字、汎用アイコン、カードの入れ子がない。差し色を足していない(D3 は色を写真に任せる)。
- **長さ:** スマホで7〜9画面(`shoot.json` の phone の screens)。
- **借り物の様式に見えないか:** 黒と金(老舗・情報商材)、等幅と札(社内の仕様書)、丸ゴシックと黄色(子ども向け)のように、別の業種に見える組み合わせになっていない。

## 2. 使いやすさ(アクセシビリティ)

- **コントラスト:** 文字は 4.5:1 以上、24px 以上の大きな文字は 3:1 以上(`audit.md`)。写真の上の文字は、9割の点で基準を満たすことを最低限とし、一部でも下回るなら、文字が明るいところ(ランプ、窓)に重なっていないかスクリーンショットで見る。
- **押しやすさ:** スマホで、押せるところの高さが 44px 以上。
- **フォーカス:** Tab キーで移動したとき、すべての押せるところに枠が見える。
- **ラベル:** フォームの欄すべてにラベルがある。必須と任意が分かる。
- **構造:** h1 は1つ、見出しの順番が飛ばない。本文へのスキップリンクと `<main>` がある。
- **代替テキスト:** `alt` が写っている内容と合っている(写真を見て確かめる)。
- **動き:** 動きを減らす設定(`prefers-reduced-motion`)で、なめらかなスクロールや動きが止まる。

## 3. 日本語

スマホ幅 320px、390px と、パソコン幅のスクリーンショットで、すべての行を読みます。

- **改行:** 1〜2文字だけが次の行に落ちていない。語の途中、日付や時刻の途中(「18:30〜/21:00」)で切れていない。閉じている「よくある質問」の答えも開いて読む(`audit.md` の「改行」も見る。ただし語の切れ目の判定は機械では完全ではないので、目でも見る)。直すときは `<span class="nw">` か `<wbr>` を使う。
- **日付:** 日付と曜日が合っている(組み立てのときにも確かめる)。
- **見出しの詰め:** 大きな見出しの「、」「。」のあとに穴が空いていない。palt が効かない書体なら、字間と個別の詰めで調整しているか。
- **句読点:** 和文の中のかっことコロンが全角。
- **言葉:** 同じものを同じ言葉で呼んでいる(参加登録/申し込み、集まり/コミュニティ)。翻訳調や宣伝の決まり文句がない。助詞の誤り、意味が二通りに読める文がない。
- **事実:** 文面の事実が `brand/<団体>/facts.md` にあるか。ないものは出典を確かめる。

## 4. 広告の着地ページ

スマホで広告から来た人の気持ちで見ます。

- **最初の画面で分かるか:** 何の集まりか、だれが運営しているか、何をすればよいか。
- **広告との一致:** 見出しが広告の約束と同じことを言っている。
- **行動は1つ:** ボタンの文言がページ中で同じ。ほかのボタンと競っていない。
- **フォーム:** 必須は2つ。任意の質問は1つ。データの扱いの要約がボタンの直前に1回だけある。送信後にお礼ページへ移る(コンバージョンを数えられる)。
- **信頼:** 正式名称、法人番号、運営者、連絡先がある。実在しない実績や人を出していない。
- **仮の値:** 角括弧の仮の値が、決められた場所(次の集まりの詳細、よくある質問)にだけある。
- **速さ:** 最初の画面の写真が最優先で読み込まれる(遅延読み込みが付いていない)。スマホの最初の転送量が大きすぎない(`shoot.json` の transferKB。目安は 400KB 以下)。

## 5. コード

- `form_test.js` がすべて OK。
- `audit.md` に NG がない。読み込みの失敗、コンソールのエラーがない。
- lp-build の [implementation.md](../../lp-build/references/implementation.md) の「これまでにはまった点」に当たるコードがない(リセットの詳細度、`hidden` が効かない、欄の名前がフォームの機能を上書きする、など)。
- 組み立てた HTML を手で直していない(`content.yaml` から組み立て直すと消える)。
