# 指摘の書き方と、確かめ方

## 指摘の書き方

指摘は1件ずつ、次の形で書きます。

| 項目 | 書くこと |
| --- | --- |
| 場所 | 節の名前と、セレクタか文面(例:最初の画面 `.hero h1` 「AIで、まちの課題を」) |
| 問題 | 何がおかしいか。見たこと、測った値 |
| 根拠 | スクリーンショットのファイル名、`audit.md` の行、測り方 |
| 影響 | なぜ困るか(だれが、どんなときに) |
| 直し方 | `content.yaml`、`theme.css`、テンプレートのどこをどう変えるか。文面なら新しい文 |
| 重さ | 高・中・低 |

好みの問題(「もっとおしゃれに」など)は指摘にしません。数値や見たことで説明できるものだけを書きます。

## 確かめ方

指摘を報告する前、直す前に、1件ずつ「本当に問題か」を確かめます。見つけた人と別の目で見るのが理想です。Claude Code ではサブエージェントに任せられます。ほかの環境では、自分で見直します。

1. **もう一度見る・測る。** スクリーンショットを撮り直す、別の画面の大きさでも見る、数値を測り直す。
2. **反証を探す。** 「これは問題ではない」と言える理由を探す。例:
   - 決められた場所にある仮の値(`[日時]` など)
   - 一部だけ基準を下回るが、文字が明るいところに重なっていない
   - 好みの問題
   - デザインの方向(D3)の決まりどおり
3. **直し方が悪さをしないか。** 直したことで別の画面の大きさが崩れないか、ほかの決まりに反しないか。
4. **確かめられたものだけを残す。** 残した指摘には、確かめた方法を書き足す。

## 直したあと

1. `content.yaml` などを直し、lp-build の `build_site.py` で組み立て直す。
2. `shoot.js`、`audit.js`、`form_test.js` をもう一度実行し、直したところのスクリーンショットを見る。
3. 前より悪くなったところがないか確かめる。
